Get one alert for every new trending search on Google Trends "Trending Now" in the countries you choose. Each alert has the search term, Google's approximate search volume, when the trend started, and the news articles Google links to it.

Schedule it hourly and you get a running feed of what people suddenly started searching for, without repeats. A trend you were already alerted about is never reported or charged again.

Why this actor

  • Reads Google's own Trending Now feed. No browser and no proxy, so runs are fast and cheap.
  • Only new trends. The actor remembers what it already reported (per monitor) and skips it next time.
  • Many countries in one run. US, GB, ZA, IN, AU, or any country code Google Trends supports.
  • Delivery built in. Dataset rows, plus an optional webhook (Make, Zapier, n8n) and an optional Slack message per run.
  • Filters. Minimum search volume and optional keywords, so you only hear about trends that matter to you.

Quick start

  1. Enter the countries you want to watch.
  2. Run once to see what is trending now.
  3. Add a schedule (for example every hour). From then on each run returns only new trends.

Input example

{
  "countries": ["US", "GB", "ZA", "IN", "AU"],
  "includeNews": true,
  "minTraffic": 1000,
  "keywords": [],
  "monitorName": "newsroom",
  "slackWebhookUrl": "https://hooks.slack.com/services/..."
}
Field What it does
countries Two-letter country codes. Default US, GB, ZA, IN, AU.
includeNews Attach Google's related news articles to each trend. Default on.
reportCurrentOnFirstRun On: the first run reports everything trending now. Off: the first run only saves a baseline and charges no alerts. Default on.
minTraffic Only report trends with at least this approximate search volume (Google shows ranges like 200+, 2000+, 50K+). 0 = no filter.
keywords Only report trends whose title or a news headline contains one of these words. Empty = everything.
monitorName Names the memory of reported trends. Use different names to run independent monitors. If empty, the name comes from your countries, keywords and minimum volume.
rememberDays A trend that has been gone from the feed this many days is forgotten (and reported again if it returns). Default 7.
webhookUrl Receives one JSON POST per run that found new trends.
slackWebhookUrl Posts one message per run listing the new trends.
maxAlertsPerRun Hard cap on alerts delivered and charged in one run. Default 500.

The run's key-value store also holds an OUTPUT record with counts: trends seen in the feeds, new trends, alerts delivered, and any country whose feed failed.

Pricing

Pay per event, platform usage included:

  • $0.005 per new trend alert ($5 per 1,000).
  • $0.001 per run start.

A run that finds nothing new costs only the start fee. An hourly monitor on 5 countries typically costs a few cents a day, depending on how fast trends change. Use maxAlertsPerRun or the run's maximum charge to cap spend.

Use cases

  • Content ideas: write posts, videos and newsletters on what is starting to trend, while it is still early.
  • Newsjacking and PR: spot stories relevant to your brand or clients the moment they take off.
  • Ad and SEO timing: launch campaigns, bid on terms or publish pages while search demand is rising.
  • Research and dashboards: build a history of trending searches per country in a dataset, sheet or database.
  • Alerts on a topic: use keywords to hear only about trends mentioning your company, product, team or industry.

Limits

  • Google's Trending Now feed lists the top trending searches per country (usually about 10 at a time), with approximate volume ranges, not exact counts.
  • This actor does not return interest-over-time charts or related queries.
  • Country codes must be ones Google Trends supports. A country whose feed fails is skipped and listed in the run summary; the rest of the run continues.
