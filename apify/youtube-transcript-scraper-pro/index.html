Example: YouTube Channel Transcripts to Plain Text

Get the transcripts of public YouTube videos, Shorts, playlists, channels or a keyword search as clean text with timestamps: one JSON row per video, with its title, channel, date, views, likes and chapters.

Price: $1 per 1,000 transcripts on the Apify free plan ($0.001 a video), from $0.70 on paid plans. Videos with no captions, or that fail, are never charged.

What people use it for:

  1. AI and RAG. Feed transcripts to ChatGPT, Claude or a vector database. Ask for chunks to get pieces of about 500 words with start and end times.

What you get

For each video:

  • The full transcript as one clean string, ready for an LLM, a search index or a document
  • Timestamped segments (start, duration, text) for subtitles, quotes and chapter work
  • Optional SRT and VTT subtitle text, and the transcript cut into chunks of about 500 words with start and end times
  • Title, channel, channel ID, duration, view count, like count, publish date, description, tags, thumbnail and description chapters
  • Which caption language you got, whether it was auto-generated, and every language the video offers

Quick start

  1. Fill in any of the four inputs: Video URLs or IDs, Channel URLs, Playlist URLs or Search keywords. You can mix them in one run.
  2. Set Max videos per channel or playlist and Max results per search to how many videos you want from each.
  3. Pick a Language and, if you want, Output formats.
  4. Click Start. Download the results as JSON, CSV, Excel or HTML, or read them through the Apify API.

Only new videos (scheduled watching)

Turn on Only new videos and put the run on an Apify schedule (for example every day). Each run then delivers only videos it has not delivered to you before, so a daily channel watch gives you just the new uploads.

{
  "channelUrls": ["https://www.youtube.com/@3blue1brown"],
  "maxVideosPerSource": 10,
  "onlyNewVideos": true,
  "stateKey": "3b1b-daily"
}
  • The state key. The list of delivered videos is kept in your own Apify key-value store named youtube-transcript-pro-seen, in a record named after State key. Leave the key empty and the actor makes one from your channel, playlist, search and video inputs, so the same inputs always share one list. Give each watch its own key if you want to change its inputs later and keep its history.
  • Not charged. A video already delivered is skipped before its transcript is fetched. It is never written to the results and never charged. The run's OUTPUT record shows how many were skipped in skippedAlreadySeen. Each run still pays the small start fee from the pricing table, even when there is nothing new.
  • Failed videos are tried again. Only videos delivered with a transcript are remembered. A video with no captions, or one YouTube blocked, is tried again on the next run.
  • Set the limits with room for new uploads. The actor lists the newest videos first and then skips the ones it already delivered, so those still take places in the list. A channel or playlist lists up to Max videos per channel or playlist videos, a search up to Max results per search, and none lists more than Max items. So with Max items at 2 and no channel limit, a channel whose 2 newest videos were already delivered gives nothing new. Skipped videos do not use up Max items for your other inputs. A daily watch of a channel that posts a few videos a day works well with a channel limit of 10.
  • Start again. Delete the record from the youtube-transcript-pro-seen store (Storage, then Key-value stores in the Apify Console), or use a new state key.
  • The list keeps the newest 20,000 video ids per key. It is saved every 10 delivered videos and at the end, so a run that stops early near its timeout keeps everything it delivered. If a run is aborted or killed instead, up to the last 10 videos it delivered may come again in the next run.

Translation

This actor does not machine-translate. In our tests on 20 Nov 2026 YouTube refused every machine-translation request (HTTP 429), from cloud and home IPs, so the Console does not offer it.

To get transcripts in another language, set language to its code. If the video has its own caption track in that language, you get it. If not, you get another track in the order below, and language tells you which.

How the language is chosen: first a track with exactly the code you asked for. Then a track with the same base code, so pt finds pt-BR or pt-PT and es finds es-419 (the one YouTube lists first). If the video has neither, you get the video's own language (the language of its auto-generated track, or its only manual track), and after that English. If it has none of these, you get the first track YouTube lists. Within a language, manual captions come before auto-generated ones unless Prefer manual captions is off. The language field always shows the code of the track you got.

API callers who send translateTo get the same thing: a caption track in that language when the video has one, otherwise the original language with translation_error set. The price is the same either way. We will update this section if YouTube's behaviour changes.

Speed and run size

In tests on 16 November 2026 a run of 30 videos took 42 seconds. On 20 November 2026 a 30-video channel run took 25 seconds at 256 MB and 26 seconds at 1,024 MB. Plan on about 45 videos a minute; long videos and blocked requests that need a retry take longer.

  • The default run timeout is 30 minutes, which should cover about 1,000 videos at that speed. The largest run we have tested is 30 videos. For bigger runs, raise Timeout in the run options before you start.
  • If a run gets close to its timeout, it normally stops about 25 seconds early instead of failing. Everything delivered so far stays in the dataset, and the videos it did not reach are listed in OUTPUT.not_processed so you can run just those again. They are not charged.
  • maxItems caps the number of videos per run (default 100, up to 10,000). A 10,000-video run needs a timeout of about 4 hours and has not been tested.
  • Default memory is 256 MB (you can raise it to 1,024 MB). The actor waits on the network, not the processor, so more memory does not make it faster. In that test the run peaked at 68 MB either way.

Use it in n8n

You need an Apify account, your Apify API token (Console, then Settings, then API & Integrations) and n8n, on n8n Cloud or your own server. No code is needed. The steps below call the actor with n8n's HTTP Request node. This input takes the 10 newest videos of a channel:

{
  "channelUrls": ["https://www.youtube.com/@3blue1brown"],
  "maxVideosPerSource": 10,
  "maxItems": 50,
  "language": "en",
  "outputFormats": ["text"]
}
  1. Add your token. In n8n, create a Header Auth credential. Name: Authorization. Value: the word Bearer, a space, then your token.
  2. Add an HTTP Request node. Method POST, URL https://api.apify.com/v2/acts/skillmerc~youtube-transcript-scraper-pro/run-sync-get-dataset-items. Authentication: Generic Credential Type, then Header Auth, then your credential. Turn on Send Body, set Body Content Type to JSON and Specify Body to Using JSON, then paste the input above.
  3. Run the node. The call waits for the run to finish and returns the result rows. n8n makes each video one item, with the fields from "Output fields". Apify ends a waiting call after 300 seconds, so keep maxItems at about 150 or less per call and split bigger jobs over several calls.
  4. Send rows to Google Sheets. Add a Google Sheets node, connect your Google account and pick "Append or Update Row" on your sheet, matched on a video_id column. Map video_id, title, channel, published_at, video_url and transcript_text to columns. Running it twice then updates rows instead of adding duplicates. A Sheets cell holds at most 50,000 characters, very roughly an hour of talk, and a longer transcript_text makes the Sheets step fail. For longer videos set "outputFormats": ["chunks"], add a Split Out node on chunks with Include set to All Other Fields, and send the rows to a second tab with Append Row. Each chunk becomes one row with its video_id, chunk_index and text. Do not match chunk rows on video_id alone, since every chunk of a video shares it.
  5. Get only new videos every day. Start the workflow with a Schedule Trigger node (for example daily at 07:00) and add "onlyNewVideos": true and "stateKey": "my-daily-watch" to the input. Each run then returns only videos it has not delivered before (see "Only new videos" above).

Apify's own n8n node works too: choose Run an Actor with skillmerc/youtube-transcript-scraper-pro, the same input and Wait for finish turned on, then Get dataset items with the run's defaultDatasetId. Run an Actor and get dataset does both in one step.

How it works

Transcripts come from YouTube's own caption tracks through its mobile player API, not from scraping the web page. Channel, playlist and search listings, and the publish date, come from YouTube's public web endpoints. YouTube often blocks cloud servers, so when a request is refused the actor retries that video through fresh proxy IPs (datacenter first, then residential). Retries are included in the price.

Limitations

  • Videos with no captions at all can't be transcribed. This is common for music videos and sports highlights. They are reported free of charge.
  • If the language you ask for isn't available (not even as a regional track such as pt-BR for pt), you get the video's own language, then English. The language field tells you which one you got. See "Translation" for the full order.
  • Channel links return the uploads on the channel's Videos tab, newest first. Shorts and live streams on the channel's other tabs are not included. Playlist links return videos in playlist order. The largest listing we have tested is 150 videos from one channel and 150 from one playlist (16 November 2026).
  • Search asks YouTube for video results only (no channels or playlists). Results can include videos without captions; they are reported free of charge.
  • publishedAfter filters the videos found. Channels list newest first, so with a channel it works like "the latest videos since". On a search or playlist it can leave fewer videos than you asked for. A video whose date YouTube does not return is kept.
  • No machine translation (see "Translation").
  • No comments or audio-to-text. Videos with no captions are not transcribed.
  • chapters holds only the chapters written as timestamps in the description. YouTube's automatic chapters are not included, so some videos that show chapters on YouTube have an empty list here.
  • Private, members-only and age-restricted videos are not read: the actor never logs in.
  • A link that contains both a video and a playlist (watch?v=...&list=...) is treated as that single video. Use the playlist?list= link to get the videos of the playlist.

Troubleshooting

Videos that fail are listed with the reason in the run's OUTPUT record (failures) and in the free failed-videos dataset. You are not charged for them. Each failure has a short reason_code next to its error text, so a script can tell "try again later" from "never":

reason_code Meaning Try again?
live_now The video is a live stream that is still on air Yes, after the stream ends
upcoming A live stream or premiere that has not started Yes, after it has aired
stream_processing A live stream that just ended; YouTube has not made its captions yet Yes, in a few hours
age_restricted YouTube asks the viewer to sign in to confirm their age No: the actor never logs in
members_only Only the channel's paying members can watch it No
private The video is private No
unavailable Removed, deleted or otherwise unavailable No
no_captions The video plays but has no caption track at all No
other Anything else, such as an empty caption track or YouTube blocking every route Often yes, later

Problems with an input link are in OUTPUT.warnings. A few notes appear only in the run log. Look up the text you see:

Message What it means What to do
no captions available for this video The video has no caption track at all, not even an auto-generated one. Nothing to fix. This actor reads captions; it does not turn audio into text.
caption track is empty YouTube lists a caption track but it has no lines. Try again later or pick another language.
not playable: LOGIN_REQUIRED (or UNPLAYABLE, ERROR or another status) YouTube will not play the video to a logged-out viewer. YouTube's reason follows the status: private, members-only, age-restricted, removed, or a live stream that has not started. The actor never logs in, so private, members-only and age-restricted videos can't be read. A live stream or premiere can be read after it has aired.
not a YouTube video, playlist or channel link A link in Video URLs is not one the actor can read. Paste a watch?v=, youtu.be/ or /shorts/ link, or use Channel URLs, Playlist URLs or Search keywords.
YouTube blocked every route we tried YouTube refused or did not answer the request from the run's own IP and from every proxy IP we tried. Run those videos again later.
not a channel link or not a playlist link (no list=) A link in Channel URLs or Playlist URLs is the wrong kind. Move it to the right field, or paste it into Video URLs, which detects the kind. Channel links need @handle, /channel/, /c/ or /user/.
skipped channel link or skipped playlist link Expand channel and playlist links in Video URLs is off, so these links in Video URLs were ignored. Turn it on, or move the link to Channel URLs or Playlist URLs.
channel link gave no videos The handle is unknown, the channel has no uploads on its Videos tab, or YouTube refused the listing. Check the link in a browser. If it works there, run it again later. Shorts and live streams are not listed.
playlist link gave no videos The playlist is private, empty or gone. Check the link in a browser while logged out.
search "..." found no videos YouTube returned no video results for that phrase. Try a broader or different phrase.
publishedAfter "..." is not a date (run log) The date could not be read, so no date filter was applied. Use the form 2026-11-01.
No videos found from the input (run log) Nothing in the input produced a video. Read OUTPUT.warnings for the reason per link.
Stopped before the run timeout (run log) The run was close to its timeout and stopped early. Videos not reached are in OUTPUT.not_processed and were not charged. Raise Timeout and run them again.
could not read ... or another short technical error (for example empty caption response) YouTube gave an answer the actor did not expect, or no answer. Run it again later. If it keeps failing, open the Issues tab with the run ID.
translation_error in a row YouTube did not translate the track, so you got the original language. See "Translation".

FAQ

Does this YouTube transcript scraper work with Shorts?

Yes. Paste the /shorts/ link like any other video link.

Can I get the transcripts of a channel or a playlist?

Yes. Paste the channel link into Channel URLs or the playlist link into Playlist URLs and set Max videos per channel or playlist. Pasting them into Video URLs also works. A channel gives its uploads from the Videos tab, newest first; a playlist gives its own order. The largest listing we have tested is 150 videos.

Can I search YouTube by keyword?

Yes. Put phrases in Search keywords and set Max results per search. Combine with Published after for recent videos only.

Which languages are supported?

Any caption language the video has. Set language to the code you want (en, es, de, pt, ko and so on). A plain code also finds regional tracks: pt finds pt-BR. If the video does not have that language you get the video's own language, then English, and the language field tells you which. available_languages lists every track on the video.

What happens with videos that have no captions?

They are listed in the OUTPUT record and the failed-videos dataset with the reason, and you are not charged. This actor reads YouTube's own caption tracks. It does not turn audio into text.

Do I get timestamps? Can I make SRT or VTT subtitle files?

Yes. Add srt or vtt to Output formats and the row carries the subtitle file as text in the srt or vtt field. Save it to a .srt or .vtt file as is. The segments format gives start, duration and text for every caption line if you want to build your own.

Can I translate transcripts?

Not by machine translation: YouTube refuses it at the moment. If the video has captions in your language, set language to its code to get them. See "Translation" above.

Does it return the upload date, likes or description?

Upload date (published_at), description, tags and thumbnail: yes, since 0.2. Likes (like_count) and description chapters (chapters): yes, in builds after 0.3.3. Comment counts: no.

Do I need a YouTube API key or a proxy?

No. You need only an Apify account. The actor handles retries and proxies itself, and they are included in the price.

Does it log in to YouTube?

No. It reads public caption data without any account.

Is it legal?

The actor reads only data that YouTube shows to anyone without logging in. Transcripts are the video owners' content and can be protected by copyright, and YouTube's terms limit automated access. You are responsible for having a lawful reason to collect and use the data, for respecting copyright, and for any personal data in it (for example under GDPR or POPIA). If in doubt, ask a lawyer.
