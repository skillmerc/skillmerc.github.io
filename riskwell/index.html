Riskwell: Risk Register & Risk Matrix for Jira

Riskwell keeps a risk register inside each Jira project. Every risk has an inherent score (before mitigation) and a residual score (after mitigation), an owner, a mitigation, a review date and the work items that carry the mitigation work. Project admins set the risk matrix for their own project. No Jira admin step is needed after install.

Getting started

  1. Install the app on your Jira site.
  2. Open a project. The project gets a Risk register tab. Press Add risk, give it a title, rate the inherent likelihood and impact, and add the owner, mitigation, review date and linked work item keys.
  3. Open a linked work item. The Riskwell risks panel in the details column shows how many open risks link it, and lists each one with both scores, the review state, the owner and the other linked work. You can add a risk for that work item from the panel.
  4. Optional: a project admin changes the matrix under Project settings, Apps, Riskwell.

The risk matrix

Each project has its own matrix. Likelihood and impact each have 3, 4 or 5 levels, and you can rename every level. Bands are set by score thresholds: medium, high and critical (everything below medium is low). The review interval is 7 to 730 days (default 90). Project admins and Jira admins can change the matrix.

When you change the size of the matrix, existing ratings are shown on the new scale (the top level stays the top level, the bottom stays the bottom). Riskwell keeps the ratings people entered, so changing back to the old size gives the original ratings again. If someone edits a risk's ratings on the new scale, those become the kept ratings.

Scores

  • Score = likelihood x impact. On a 5x5 matrix scores run from 1 to 25.
  • Inherent is the risk before any mitigation. Residual is the risk with the mitigation in place. Until the residual is rated it equals the inherent score.
  • A residual score above the inherent score is allowed but shows a warning.
  • The register shows counts of active risks, residual critical and high risks, overdue reviews, risks with no mitigation, and how much mitigation cut the total score. The heat map shows likelihood by impact, on inherent or residual scores. Press a cell to list its risks.

Review reminders

Once a day Riskwell checks review dates. When a risk with an owner is due or overdue, the owner gets one Jira notification email for that review date, sent through the first linked work item. Risks without a linked work item still show as overdue in the register. Press Mark reviewed to set the next review date from the matrix interval.

Rovo agent

If your site has Rovo, the Riskwell agent can draft 3 to 6 risks from an epic (using your project's scale names), summarise a project's register, and list overdue risk reviews. The agent only reads. Drafts are text for you to judge; nothing is saved until a person adds the risk in the register.

CSV export

Export CSV on the register opens the file text in a dialog to copy (the Forge UI cannot start a file download). Columns include both scores and bands, owner display name, status, treatment, review date and linked keys. Cells that start with = + - or @ get a leading apostrophe so spreadsheets do not run them as formulas. The text uses LF line ends.

Licence

On the Atlassian Marketplace the app is paid through Atlassian, with Atlassian's free trial. If the licence for a site is not active, the register, panel and CSV export keep working, but risks and the matrix cannot be changed until the licence is active again.

Data

Built on Atlassian Forge. Risks are kept in Forge storage in your Atlassian site. The app calls no outside service. Privacy policy. Terms of use.
