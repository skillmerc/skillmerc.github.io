Ship Rules for Jira

Ship rules say what must be true before a Jira work item ships: tests linked, reviewed by a person, rollback noted, security review for sign-in changes. You set them per project, by work type, label and component.

People attach evidence on the work item. Coding agents read the same rules and attach evidence through five tools on the Atlassian MCP server. Rules you mark "a person must confirm" stay open until a person confirms them in Jira, whatever an agent attaches.

Getting started

  1. Install the app on your Jira site.
  2. Open a project, then Project settings, Apps, Ship rules. A project admin adds rules or loads the sample rules. Each rule says what must be true, who can satisfy it (a person or an agent, or a person only), the evidence it needs (a link, a note, or either), and which work types, labels and components it applies to.
  3. Open any work item in that project. The Ship rules panel shows each rule, its evidence and whether the item is ready to ship. Attach evidence, confirm a rule, or waive it with a reason.
  4. The project's Ship readiness page lists the open work items that are not ready, by item or by rule. In JQL you can search, for example, shipReady = "no" AND shipMissing = "tests-linked".
  5. Optional: when a work item moves to Done with rules still open, the app adds a comment that lists them. A project admin can turn this off.

Licence

On the Atlassian Marketplace the app is paid through Atlassian, with Atlassian's free trial. If the licence for a site is not active, rules, readiness and evidence stay readable, but nothing can be added or changed until the licence is active again.

For coding agents

The open-source skill file and an AGENTS.md snippet are at github.com/skillmerc/ship-rules-skill.

ToolWhat it does
get-ship-readinessThe rules that apply to one work item, the evidence on each, whether it is ready, and the next steps.
check-ready-to-shipA short yes or no with the open rules and reasons.
attach-ship-evidenceAttach a link or a note to one rule. Needs edit permission on the work item.
list-blocked-work-itemsOpen work items of a project that are not ready, or only those blocked on one rule.
get-ship-rulesEvery rule of a project, or the rules for one work item.
